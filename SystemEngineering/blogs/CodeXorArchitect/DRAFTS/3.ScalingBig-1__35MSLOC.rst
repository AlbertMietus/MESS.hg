===============

You shouldn't build a 350m-high skyscraper in the same way as a bike shed. Likewise, coding a 35M SLOC Linux kernel takes a
different style than `HelloWorld`. Still, all software starts small. Even Linux did fit on a single page, 35 years ago.
|BR|
Today's question is: How can architecture help to scale software?

Linux is based on the *'Common Unix Architecture'*. A well-known, very straightforward structure, with drivers, CPU
abstraction, file- & networking-IO, and a bit more.  Even version v0.0.1 of the Linux kernel used it. Without it, Linux
would not scale that well.

Building a big codebase is a lot of work. With common estimation statistics, we know that building Linux cost
around 10kMY. Or, as I prefer: **20k Sprints** That is roughly 30 teams for 35 years.
|BR|
When it starts, everything is small and smooth; probably you know every line of ``HelloWorld``. But that approach doesn't
scale -- you can’t memorize millions of lines.  Still, no single SW-engineer should ever get lost in the
codebase. Otherwise nobody can add features, and the system can't grow. Here this Common Unix Architecture helped Linux a lot.

All source files are grouped in (sub)dirs along this architecture.  Roughly, 80% of all code is in the `drivers`
directory. When you're not working on drivers, you can skip the biggest portion of the code in a blink. And this structure
repeats.
|BR|
To improve, for example, the real-time behavior of the scheduler, you can skip even more. Not only are all drivers-lines
irrelevant, the hardware abstraction and all IO modules are unimportant too. Only about 0.2% of all code is for the scheduler;
and it's easy to find (It’s in ``/kernel/sched/``:-).
|BR|
The real-time part of the scheduler is even smaller; it's less than 1/100 of 1% of the codebase. A meager 2k lines; you
probably go over it in a few days.

Architecture brings structure; architecture gives the ability to find stuff. And with that, the option to change a few
lines, without reading most of the code.

Next time you start with something that potentially can become bigger than 5 lines: Start with a sound
architecture. Always make sure there is only one logical spot for all those further lines. One day, you can add as many
SW-bricklayers as you need due to your “skyscraper” architecture.
