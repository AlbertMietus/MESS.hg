Every SW-Engineer who knows Linux (34M SLOC), started with ``HelloWorld`` (5 lines). But only a few understand the effect of scale
|BR|
Big is not beautiful, big is hard work! Big code-bases needs a mindful architecture, to prevent it from code-rot.

Let’s start with an simple question. How much work is to write something new, like Linux?
|BR|
Using classic statistics, and modern engineering practices, it would roughly be **20kSprints**! That is 1 team for
almost 1000 year! Or 33 teams for 33 years. Notice, that when Linux started about 35 years ago, the all his code fitted
on 1 page of A0!

It did scale a bit! But remember: Linux was *easy*. It’s based on the common Unix architecture; starting with ‘Multix’ (end 196X),
and boosted when K&R invented C (1973). The result is a very straightforward structure: drivers, CPU-abstraction, file-
& networking-IO, and a bit more.

A new question: What is bigger: the scheduler or the drivers?
|BR|
There are many text-books on scheduler, and especially on the real-time part of it. Still the scheduler is far below 1%,
when counting SLOC- and the real-time part it about 1/1000 of a promille -- about two thousand lines!
About 80% of the Linux source code is for drivers; a growing factor as more and more hardware is supported.

Now, the real question: How is it possible that so many engineers can work on Linux; some of them quite young.?
|BR|
The answer is, again, simple: architecture and structure!
