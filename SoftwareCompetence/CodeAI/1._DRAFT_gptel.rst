Refactor you chats
-------------------

Chatting with an LLM via an app or web-tool is convenient, but the conversation can go haywire.  More than
once, I press `send` instead of `newline`, those wrong questions give never to be read answers.  Or, I have
some good side-questions, which are unrelated to the main discussion.  All of that makes the dialog hard to
understand, when reading it back a few days later. Moreover, all those irrelevant collectibles eat up tokes,
round after round.
|BR|
Even more cumbersome, when using several AI-tools, and/or multiple models, all information becomes spread and I
almost need an meta-AI tool to find my details..

As a (former) software-engineer, I know the solution. When it was code, I would refactor it; using the power of
a proper editor.


GPTEL
-----

This is what tools as **gptel** provide! Even though `gptel` it’s an Emacs extension, similar plugins exist for
all major (open) editors -- see the sidebar.
|BR|
Now, everybody can use the power of her/his favorite editor, to rewrite the discussions with the LLM(s) you
prefer.  You can even save it and continue a day later. Spiting-out those side-questions is trivial; which make
them easier to find. You main line of thoughts become clean again. And, as a bonus, the save tokens, cost and
speed-up the slow long conversation.





The best of 2 worlds
---------------------

It’s like a chat with your web-LLM: type, send, and continue. As `gptel` is *async*, the answers will be added
to your buffer -- but you do not need to wait! Moreover, you typically work in a markdown buffer, giving you
highlight by default, like it can fold sections in and out
